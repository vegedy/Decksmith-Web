# Requirement traceability

`SPEC.md` is authoritative. Final audit: 2026-09-25. Each of the **87** mandatory
requirements below was reviewed individually against its acceptance criterion.
**86 verified; 0 partially implemented; 0 not implemented; 1 not verifiable in the
current environment (D-05).** This is not unconditional project completion.

Status vocabulary: **verified** requires observed validation beyond source existence;
**partially implemented** identifies an unmet implementation part; **not implemented**
means absent; **not verifiable in the current environment** records an evidence barrier.
Verification is scoped to the bundled showcase, supported configurations and stated
checks, not every possible authored deck. Physical projector suitability remains open.
Optional untested variants are called out without inventing additional requirements.

[Final audit evidence](VALIDATION.md#independent-final-audit-2026-09-25) records fresh
commands/artifacts and limitations. Earlier validation records are historical evidence,
not a substitute for this audit. [Component index](COMPONENTS.md) links editable examples;
[decisions](DECISIONS.md) explains differences from illustrative SPEC examples.
